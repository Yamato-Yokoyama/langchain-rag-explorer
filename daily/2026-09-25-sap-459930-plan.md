### 3. MCPミニサーバー = レシート自動化と合体させる

今困ってる「レシートPDFを手動でGeminiにかけてJSONに変換してる」作業を、そのままMCPツール化する。一石二鳥:

- 個人的に欲しかった自動化が手に入る
- 求人票が名指しする「MCP」の実体験サンプルになる

- [ ] 既存の手動フロー(PDF → Gemini手動投入 → JSON貼り付け)を確認し、`src/load_receipts.py`が期待するJSONスキーマを整理
- [ ] Geminiのマルチモーダル呼び出し(PDF/画像入力 → 構造化JSON出力)を1関数として切り出す(`hello_gemini.py`の延長)
- [ ] その関数を1つのMCPツールとして公開する最小のMCPサーバー(stdio)を書く
- [ ] Claude Desktop等からそのMCPサーバーを呼び出して、実際にレシートPDF→JSONが動くことを確認
- [ ] (ストレッチ・任意、月曜までは不要) 音声入力対応、別APIキー取得は今回はスキップしてGEMINI_API_KEY使い回しでOK

**MCPって何か念のため一言で**: Claudeのようなモデルが外部のツールやデータに「共通の作法」でアクセスするためのプロトコル。今回作るのは「レシートPDFを渡すと構造化JSONを返す」という1つのツールを、その作法に沿って公開するだけの小さいサーバー。

### 2. 永続化checkpointer(最後・一番自信ないところ)

- [ ] `graph_router.py`の`MemorySaver()` → `SqliteSaver`(`langgraph.checkpoint.sqlite`)に差し替え
- [ ] 差し替え後、プロセスを再起動しても同じ`thread_id`で会話履歴が復元されることを確認

**checkpointerって何か念のため一言で**: LangGraphが「今この会話がどこまで進んだか」を保存しておく仕組み。今は`MemorySaver`でプロセスのメモリ上だけに保存してるので、アプリを再起動すると会話が消える。`SqliteSaver`に変えるとファイルに保存されるので、再起動しても続きから会話できるようになる。
