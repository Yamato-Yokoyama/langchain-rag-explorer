# 学習様式と、RAGの中でどの方向を目指すか

> [docs/why.md](why.md)から分割(2026-08-27)。

## 学習様式: 反復→感覚定着→試験問題でブラッシュアップ

Lasso/Ridgeを学んだ時と同じパターン(`daily/2026-08-13.md`学び⑤で既に言語化済み: 「プロジェクトで手を動かして理論と実装が繋がった時に定着」)を、PCA・SVD・Naive Bayesのようなまだ自信がないトピックにも当てはめる。**厳密な暗記ではなく、手を動かして繰り返すことで感覚レベルの直感を先に作り、試験前に問題演習で言語化を仕上げる**、という2段階方式。この方式は既に実績があるので(Lasso=係数を極端に0にする、Ridgeは0にしないという直感が今も残っている)、新しいトピックにも踏襲してよい。

## RAGの中でどの方向を目指すか

「RAGといっても色々あって、どこを目指せばいいか分からない」への回答。RAGは大きく分けて以下の方向がある:

| 方向 | 中心的な問い | このプロジェクトでの実績 |
|---|---|---|
| **検索品質/IR理論寄り** | なぜこの検索は失敗するか、どう直すか | ★実績あり(Speech Actミスマッチ、QUD型分類、company フィルタ) |
| エージェント/オーケストレーション | 複数ステップの計画・ツール利用をどう設計するか | これから(LangGraph) |
| インフラ/スケール | 大規模データでの検索速度・コスト | 未着手(`daily/interview-prep/when-vector-db-becomes-necessary.md`で計画のみ) |
| マルチモーダル | 画像・音声を含む検索 | 未着手 |
| **評価・信頼性(hallucination/uncertainty)** | LLMの回答がどれだけ根拠に基づいているか、不確実性をどう扱うか | 種が既にある(2026-08-27、ベルリン/ケルンの生成側hallucinationを保留事項として記録済み、`daily/2026-08-27.md`) |

自分から見て、既に実績がある「検索品質/IR理論寄り」が現状の主戦場。加えて、最近の講演で興味を持った「モデルの不確実性の数学的な表現」は、既に自分のプロジェクトの中に伏線(hallucination観察)がある。**新しいトレンドを追うのではなく、既に自分の中にある2つの糸(検索診断+信頼性評価)を伸ばす、という選び方が筋が通っている。**

この方向づけは[specialty-positioning.md](specialty-positioning.md)の専門性(システムの失敗を言語理論で診断できるエンジニア)と直結している。

## 論文を読む習慣・追いかける研究者について

まだ手を付けていない領域。仕組みだけメモしておく: Google Scholarの著者プロフィールをFollowすると新着論文がメール通知される、Semantic ScholarのFollow Authorも同様、ACL Anthology(CL/NLP分野の主要論文誌)は自分の専攻と直結する。**「誰を追うか」は自分の専門性が固まってから決める方が自然**、逆に専門性を決めるために誰かを先に選ぶと本末転倒になりやすい。上記の2つの方向(検索診断/信頼性評価)で実際に論文を1本読んでみて、そこから著者・引用を辿る方が、Twitterで探すより確実。

現状の運用: 論文はGoogle Scholarのフォローだけで十分。たまに通知が来て面白そうなら概要(abstract)だけ読む、というライトな習慣で続ける(2026-08-27時点の結論)。
